# Code map

Where things live and which files a typical change touches. Read this first; open the full docs only for the section you need (links below). Keep it short: one line per file, update it when you add, rename or delete a file.

Rules and reasons: [Architecture](Architecture.md), [Subsystems](Subsystems.md), [Resource creation](ResourceCreation.md), [Scene, ECS and systems](SceneAndECS.md), [Scripting](Scripting.md) (writing the game's code), [Test bed](TestBed.md). Unfinished work is tagged in code: search `TODO(assets)` (and `Known gaps` in each doc).

## Game: `Game/src`

The game's own code (the Sandbox project's scripts), a static library linked by Oxygen and the Runtime. Its pre-build step runs the reflection generator. Its planned shape (shared `Data/`, `State/`, `Rules/`, `Views/`, `Scripts/Common/`; `Scripts/<Area>/` for what only one area or scene uses) and the rules for game scripts are in the wiki's [Scripting plan](https://github.com/joelnl74/Hydro/wiki/Scripting-Plan) (the files moved there Nov 1, 2026, SC8a: `State/`, `Rules/`, `Views/`, `Scripts/Common/`, `Scripts/Field/`, `Scripts/Battle/`, one folder per area, `Scripts/Examples/` and `Scripts/Tests/`; the scripts are still split further in SC8e to g).

## Gotchas

- **Box2D** is a git submodule at `Hydro/vendor/box2d`, pinned to v3.1.1 (`git submodule update --init Hydro/vendor/box2d`). `Hydro/vendor/box2d.premake5.lua` builds it as a C17 static library; Debug is optimised on purpose (see the comment there). Only `Physics/` includes `<box2d/box2d.h>`.
- **Jolt Physics** is a git submodule at `Hydro/vendor/JoltPhysics`, pinned to v5.6.0 (`git submodule update --init Hydro/vendor/JoltPhysics`). `Hydro/vendor/JoltPhysics.premake5.lua` builds it as a C++17 static library with no debug renderer, profiler, object stream or AVX; the same defines (`JoltDefines()` in `Dependencies.lua`) must be used by every project that includes Jolt headers. Only `Physics/` includes `<Jolt/...>`.
- **cgltf** (vendored single header `Hydro/vendor/cgltf/cgltf.h`, v1.14, MIT): the glTF reader; its implementation is compiled in `Renderer/MeshImporter.cpp` (`CGLTF_IMPLEMENTATION`). It replaced tinyobjloader (`Hydro/vendor/Obj-loader`, unused).
- **ImGuizmo** (vendored `Hydro/vendor/ImGuizmo/ImGuizmo.h` / `.cpp`, MIT; commit in its `README.txt`): the Editor window's transform gizmo. Compiled into **Oxygen** only (`Oxygen/premake5.lua`, warnings off), included as `<ImGuizmo.h>` (`IncludeDir.ImGuizmo`); the engine never uses it.
- **Old EnTT** (vendored single header `Hydro/vendor/entt/entt.hpp`, no version macro): `registry.has<T>`, `view.get<A, B>(e)`; no `all_of`/`any_of` (upgrade is Roadmap E2).
- **Line endings**: CRLF in the working copy for sources and docs (`.gitattributes`); `*.sh` is LF.
- **Style**: `namespace Hydro` only, no `!` (use `== false` / `== nullptr`), braces on every body, `m_PascalCase`. See the skill or [Architecture](Architecture.md#code-conventions).
- `Renderer2D.h` and `Renderer.h` still include `vulkan.h` (A7; `RenderView.h` no longer does); don't add Vulkan to other `Renderer/` headers.
- Shaders are compiled at runtime by shaderc from `assets/shaders/...`, relative to the working directory (run Oxygen from the `Oxygen/` folder).

`scripts/lint_conventions.py [files or folders...]`: the code conventions, checked (default `Hydro/src`, `Oxygen/src`, `Game/src` and `Runtime/src`; Python, no packages): no `!` operator, braces on every `if` / `else` / `for` / `while` / `do` body, only `namespace Hydro` (plus `std` / `YAML` for their specialisations), `m_` / `s_` names in PascalCase, and no include from another area's `Game/src/Scripts/<Area>/` (except `Scripts/Common/`). Comments, strings and preprocessor lines are ignored; vendor, generated files and the ImGui backends skipped. `file:line: rule: message`, exit 1 on any. In CI. Warnings (`--warnings` lists them, never fail): dates and plan IDs in comments, comments over two lines, lines over 140 columns, files over 1000 lines.

`scripts/validate_project.py [project folder]`: the project's scenes, prefabs, definitions and data tables checked against the code, without the engine (Scripting plan SC5; PyYAML). What exists comes from the reflection generator's reading of the headers. Errors (exit 1): an unregistered script, one bound twice, a value of the wrong type, an empty `Required` asset / row / reference, a reference to an entity not in the file or without the `ComponentRef<T>`'s `T`, an asset handle no file has or of the wrong kind, a row reference to a missing table or row (also inside data files), an unregistered data type. Warnings: saved values no property reads (kept), former names still in files. In CI.

## Tools

`scripts/Build.bat [Debug|Release|Dist] [--project <name>] [--rebuild] [--no-generate] [--no-pause]`: premake + MSBuild from the command line, logs in `bin/logs/`. `scripts/Package.bat [Release|Distribution] [--project <file.hyproj>] [--no-build] [--no-pause]`: a standalone build: builds `Runtime`, copies it as `<Project>.exe` with `shaderc_shared.dll`, `Oxygen/assets/shaders` and the project file + asset folder into `Builds/<Project>-<Kind>/` (gitignored), writes `build-info.txt`. `scripts/RunOxygen.bat [config]`: starts the built editor in `Oxygen/`.

`Tools/ReflectionGenerator/generate_reflection.py [repo_root] [--source DIR]... [--output FILE] [--data-output FILE] [--check]`: the reflection generator (Python 3.9+, no packages).
