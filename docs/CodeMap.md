# Code map

Where things live and which files a typical change touches. Read this first; open the full docs only for the section you need (links below). Keep it short: one line per file, update it when you add, rename or delete a file.

Rules and reasons: [Architecture](Architecture.md), [Subsystems](Subsystems.md), [Resource creation](ResourceCreation.md), [Scene, ECS and systems](SceneAndECS.md), [Test bed](TestBed.md). Unfinished work is tagged in code: search `TODO(assets)` (and `Known gaps` in each doc).

## Gotchas

- **Box2D** is a git submodule at `Hydro/vendor/box2d`, pinned to v3.1.1 (`git submodule update --init Hydro/vendor/box2d`). `Hydro/vendor/box2d.premake5.lua` builds it as a C17 static library; Debug is optimised on purpose (see the comment there). Only `Physics/` includes `<box2d/box2d.h>`.
- **Jolt Physics** is a git submodule at `Hydro/vendor/JoltPhysics`, pinned to v5.6.0 (`git submodule update --init Hydro/vendor/JoltPhysics`). `Hydro/vendor/JoltPhysics.premake5.lua` builds it as a C++17 static library with no debug renderer, profiler, object stream or AVX; the same defines (`JoltDefines()` in `Dependencies.lua`) must be used by every project that includes Jolt headers. Only `Physics/` includes `<Jolt/...>`.
- **cgltf** (vendored single header `Hydro/vendor/cgltf/cgltf.h`, v1.14, MIT): the glTF reader; its implementation is compiled in `Renderer/MeshImporter.cpp` (`CGLTF_IMPLEMENTATION`). It replaced tinyobjloader (`Hydro/vendor/Obj-loader`, unused).
- **ImGuizmo** (vendored `Hydro/vendor/ImGuizmo/ImGuizmo.h` / `.cpp`, MIT; commit in its `README.txt`): the Editor window's transform gizmo. Compiled into **Oxygen** only (`Oxygen/premake5.lua`, warnings off), included as `<ImGuizmo.h>` (`IncludeDir.ImGuizmo`); the engine never uses it.
- **Old EnTT** (vendored single header `Hydro/vendor/entt/entt.hpp`, no version macro): `registry.has<T>`, `view.get<A, B>(e)`; no `all_of`/`any_of` (upgrade is Roadmap E2).
- **Line endings**: CRLF in the working copy for sources and docs (`.gitattributes`); `*.sh` is LF.
- **Style**: `namespace Hydro` only, no `!` (use `== false` / `== nullptr`), braces on every body, `m_PascalCase`. See the skill or [Architecture](Architecture.md#code-conventions).
- `Renderer2D.h` and `Renderer.h` still include `vulkan.h` (A7; `RenderView.h` no longer does); don't add Vulkan to other `Renderer/` headers.
- Shaders are compiled at runtime by shaderc from `assets/shaders/...`, relative to the working directory (run Oxygen from the `Oxygen/` folder).

`scripts/test_data.sh`: headless tests of definitions and data tables and of script bindings: the generator's `HY_DATA` / `HY_ENUM` / data-reference / `FormerName` checks (`Tools/DataTests/test_generator.py`), the serializer's round trips, former names (`TestFormerNames`), `Data::Get` / `GetRow` / `GetTable` / `Validate` with reloads and the editing operations (`DataEditing`, saving) (`Tools/DataTests/DataRoundTripTest.cpp` with the types in `DataTestTypes.h`, built with g++ against the engine's `Data/` sources and a stand-in `AssetManager`, `TestAssetManager.cpp`; `ScriptSerializerTest.cpp`: script bindings' former names, kept values, references and one script of a class; `GameRulesTest.cpp`: the game's `Rules/` (battle and loot) on fixed numbers, against `ScriptRegistry` and `ScriptSerializer`; yaml-cpp is built once into `/tmp/hydro-check`).

`scripts/check.sh [files...]`: g++ `-fsyntax-only -Wall -Wextra` over the engine, editor, game and runtime sources (Windows-only files skipped), glslang over the shaders, then the two scripts below (the conventions of the given files, or all; the project validation always). Linux/WSL; downloads Vulkan-Headers, shaderc headers and builds glslang once into `/tmp/hydro-check`. Not a substitute for an MSVC `/W4` build.

`scripts/lint_conventions.py [files or folders...]`: the code conventions, checked (Scripting plan SC6; default `Hydro/src` and `Game/src`; Python, no packages): no `!` operator, braces on every `if` / `else` / `for` / `while` / `do` body, only `namespace Hydro` (plus `std` / `YAML` for their specialisations), `m_` / `s_` names in PascalCase, and no include from another area's `Game/src/Scripts/<Area>/` (except `Scripts/Common/`). `scripts/validate_project.py [project folder]`: the project's scenes, prefabs, definitions and data tables checked against the code, without the engine (Scripting plan SC5; PyYAML). What exists comes from the reflection generator's reading of the headers. Errors (exit 1): an unregistered script, one bound twice, a value of the wrong type, an empty `Required` asset / row / reference, a reference to an entity not in the file or without the `ComponentRef<T>`'s `T`, an asset handle no file has or of the wrong kind, a row reference to a missing table or row (also inside data files), an unregistered data type. Warnings: saved values no property reads (kept), former names still in files. In CI.
