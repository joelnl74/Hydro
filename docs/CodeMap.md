# Code map

Where things live and which files a typical change touches. Read this first; open the full docs only for the section you need (links below). Keep it short: one line per file, update it when you add, rename or delete a file.

Rules and reasons: [Architecture](Architecture.md), [Subsystems](Subsystems.md), [Resource creation](ResourceCreation.md), [Scene, ECS and systems](SceneAndECS.md), [Scripting](Scripting.md) (writing the game's code), [Test bed](TestBed.md). Unfinished work is tagged in code: search `TODO(assets)` (and `Known gaps` in each doc).

## Gotchas

- **Box2D** is a git submodule at `Hydro/vendor/box2d`, pinned to v3.1.1 (`git submodule update --init Hydro/vendor/box2d`). `Hydro/vendor/box2d.premake5.lua` builds it as a C17 static library; Debug is optimised on purpose (see the comment there). Only `Physics/` includes `<box2d/box2d.h>`.
- **Jolt Physics** is a git submodule at `Hydro/vendor/JoltPhysics`, pinned to v5.6.0 (`git submodule update --init Hydro/vendor/JoltPhysics`). `Hydro/vendor/JoltPhysics.premake5.lua` builds it as a C++17 static library with no debug renderer, profiler, object stream or AVX; the same defines (`JoltDefines()` in `Dependencies.lua`) must be used by every project that includes Jolt headers. Only `Physics/` includes `<Jolt/...>`.
- **cgltf** (vendored single header `Hydro/vendor/cgltf/cgltf.h`, v1.14, MIT): the glTF reader; its implementation is compiled in `Renderer/MeshImporter.cpp` (`CGLTF_IMPLEMENTATION`). It replaced tinyobjloader (`Hydro/vendor/Obj-loader`, unused).
- **ImGuizmo** (vendored `Hydro/vendor/ImGuizmo/ImGuizmo.h` / `.cpp`, MIT; commit in its `README.txt`): the Editor window's transform gizmo. Compiled into **Oxygen** only (`Oxygen/premake5.lua`, warnings off), included as `<ImGuizmo.h>` (`IncludeDir.ImGuizmo`); the engine never uses it.
- **Old EnTT** (vendored single header `Hydro/vendor/entt/entt.hpp`, no version macro): `registry.has<T>`, `view.get<A, B>(e)`; no `all_of`/`any_of` (upgrade is Roadmap E2).
- **Line endings**: CRLF in the working copy for sources and docs (`.gitattributes`); `*.sh` is LF.
- **Style**: `namespace Hydro` only, no `!` (use `== false` / `== nullptr`), braces on every body, `m_PascalCase`. See the skill or [Architecture](Architecture.md#code-conventions).
- `Renderer2D.h` and `Renderer.h` still include `vulkan.h` (A7; `RenderView.h` no longer does); don't add Vulkan to other `Renderer/` headers.
- Shaders are compiled at runtime by shaderc. They live in `Hydro/assets/shaders` and are named relative to the engine's resource folder (`"shaders/mesh.vert"`); every Oxygen and Runtime build copies `Hydro/assets` (and Oxygen's `Oxygen/assets`) next to the exe, and Oxygen's Debug/Release read the source folders first (hot reload).

## Checking without Windows







`scripts/compare_captures.py a.png b.png [--out diff.png]`: compares two view captures (Capture menu, F9) pixel by pixel; exit code 0 when they match (Pillow).



`scripts/hydro_workspace.py`: reads `hydro-workspace.json` for the tools (`--workspace <dir>`, else `HYDRO_WORKSPACE`, else the engine repository; `--get GameSource|DefaultProject|...` for shell scripts); the reflection generator, `check.sh`, `lint_conventions.py`, `validate_project.py` and `test_data.sh` take the game's code and project from it.

`scripts/test_data.sh [--game-tests <file.cpp>... [--workspace <dir>]]`: headless tests of definitions and data tables and of script bindings: the generator's `HY_DATA` / `HY_ENUM` / data-reference / `FormerName` checks (`Tools/DataTests/test_generator.py`), the serializer's round trips, former names (`TestFormerNames`), `Data::Get` / `GetRow` / `GetTable` / `Validate` with reloads and the editing operations (`DataEditing`, saving) (`Tools/DataTests/DataRoundTripTest.cpp` with the types in `DataTestTypes.h`, built with g++ against the engine's `Data/` sources and a stand-in `AssetManager`, `TestAssetManager.cpp`; `ScriptSerializerTest.cpp`: script bindings' former names, kept values, references and one script of a class; a game's own rule tests with `--game-tests <file.cpp>...` (Eonlore: `GameRulesTest.cpp`, its `Rules/` on fixed numbers; built against the workspace's game code, `-DHY_GAME_TESTS`); yaml-cpp is built once into `/tmp/hydro-check`).

`scripts/check.sh [--workspace <dir>] [files...]`: g++ `-fsyntax-only -Wall -Wextra` over the engine, editor, game and runtime sources (Windows-only files skipped), glslang over the shaders, then the two scripts below (the conventions of the given files, or all; the project validation always). Linux/WSL; downloads Vulkan-Headers, shaderc headers and builds glslang once into `/tmp/hydro-check`. Not a substitute for an MSVC `/W4` build.

`scripts/lint_conventions.py [--workspace <dir>] [files or folders...]`: the code conventions, checked (default `Hydro/src`, `Oxygen/src`, `Runtime/src` and the workspace's game code; Python, no packages): no `!` operator, braces on every `if` / `else` / `for` / `while` / `do` body, only `namespace Hydro` (plus `std` / `YAML` for their specialisations), `m_` / `s_` names in PascalCase, and no include from another area's `Game/src/Scripts/<Area>/` (except `Scripts/Common/`). Comments, strings and preprocessor lines are ignored; vendor, generated files and the ImGui backends skipped. `file:line: rule: message`, exit 1 on any. In CI. Warnings (`--warnings` lists them, never fail): dates and plan IDs in comments, comments over two lines, lines over 140 columns, files over 1000 lines.

`scripts/validate_project.py [--workspace <dir>] [project folder]` (default: the workspace's `DefaultProject`): the project's scenes, prefabs, definitions and data tables checked against the code, without the engine (Scripting plan SC5; PyYAML). What exists comes from the reflection generator's reading of the headers. Errors (exit 1): an unregistered script, one bound twice, a value of the wrong type, an empty `Required` asset / row / reference, a reference to an entity not in the file or without the `ComponentRef<T>`'s `T`, an asset handle no file has or of the wrong kind, a row reference to a missing table or row (also inside data files), an unregistered data type. Warnings: saved values no property reads (kept), former names still in files. In CI.

## Tools

`Engine.lua`, `hydro-workspace.json`, `premake5.lua`: a workspace's build (see [Workspaces](Architecture.md#workspaces)); `Sample/` is a second workspace (the engine's small test game and project). `scripts/Build.bat [Debug|Release|Dist] [--workspace <dir>] [--project <name>] [--rebuild] [--no-generate] [--no-pause]`: premake + MSBuild from the command line, logs in `<workspace>/bin/logs/`. `scripts/Package.bat [Release|Distribution] [--workspace <dir>] [--project <file.hyproj>] [--no-build] [--no-pause]`: a standalone build: builds the workspace's `Runtime`, copies it as `<Project>.exe` with `shaderc_shared.dll`, its `assets/` (the engine's files) and the project file + asset folder into `<workspace>/Builds/<Project>-<Kind>/` (gitignored), writes `build-info.txt`. `scripts/RunOxygen.bat [config]`: starts the built editor.

`Tools/ReflectionGenerator/generate_reflection.py [repo_root] [--source DIR]... [--output FILE] [--data-output FILE] [--check]`: the reflection generator (Python 3.9+, no packages). Scans `Hydro/src` and `Game/src` headers (or the `--source` folders) for `HY_SCRIPT()` / `HY_PROPERTY(...)`, `HY_DATA(...)` and `HY_ENUM()`, comments ignored, and writes `Game/src/Generated/GeneratedScriptReflection.cpp` and `GeneratedDataReflection.cpp` (or `--output` / `--data-output`, CRLF) when they change; `--check` writes nothing and exits 1 when either is out of date; exit code 1 with the file and line on an unsupported declaration. Run by the game library's pre-build step (`HydroGameLibrary` in `Engine.lua`: `--source Hydro/src --source <game>/src` with the outputs in the game's `Generated/`; `py`, Windows).
